# 四場論壇的日期大字改用稿字形 SVG

[2026-08-12 的那份文件](./2026-08-12-forum1-text-art-design.md) 把大標／副標／引言／地點／
講者姓名換成了稿匯出的 SVG，但第五節明寫「日期組本文件不涵蓋」——
因為日期不是「一行文字」，而是一塊 grid：`year` 一格、`date` 拆成 `mm`／`/`／`dd` 三格、
`weekday` 再套一圈 CSS 畫的圓框。這份文件補上那一塊。

範圍：**四場 × 三斷點，全部**（共 9 行 × 3 斷點 ＝ 27 個素材檔）。

相關檔案：

| 檔案 | 角色 |
| --- | --- |
| `app/types/forum.ts` | `ForumArtByBp`、`ForumEvent.dateArt` |
| `app/locales/section2.json` | 四場的 `dateArt`（逐行 × 逐斷點） |
| `app/components/02.forum/ForumEvent.vue` | `dateLines` computed；`--date-base`；`.forum-event__date-line` |
| `public/img/forum/forum<N>-date-<bp>-<行>.svg` | 27 份素材 |
| `test/forum-text-art.spec.ts` | 後半段的「日期大字（dateArt）」describe |

## 一、為什麼是「整行一筆」而不是「逐格替換」

稿把日期整行 outline 成**一條 path**，而且 **星期的圓框也在同一條裡**
（`get_metadata` 看 `2652:55083` → 子節點只有「09」與「15 ⊜」兩個 Group，圓框在後者內）。
要逐格替換就得先把圓框從 path 裡切出來，再讓 CSS 的圓框與稿的圓框對齊 ——
換來的只有「格子還在」，沒有任何好處。

所以：**一行 ＝ 一筆素材**，行的構成照原本 grid 的列切：

| 行數 | 內容 | 場次 |
| --- | --- | --- |
| 2 | `2026` ／ `09/09 三` | 論壇一、三、四 |
| 3 | `2026` ／ `09` ／ `15 二` | 論壇二（階梯式） |

行數由 `dateArt.length` 決定，不由 `layout` 推 —— 資料說幾行就幾行。
真文字則一律從 `year` / `date` / `weekday` **組**出來（`dateLines` computed），
不在 `dateArt` 裡另存一份：文案只有一處，校稿只改那三個欄位。

`__date-year` / `-mm` / `-slash` / `-dd` / `-weekday` 五個 class 與它們的 CSS 全部移除
（含那圈 `border-radius: 50%` 的圓框）。`__date-coreslash` 留著 —— 那一撇是**功能**
（橘核心經過時逐段畫出），不是素材，稿的日期節點裡也本來就沒有它。

## 二、幾何為什麼不會動：行盒高度 ＋ grid 列高

`.forum-event__date` 是設計線的錨點元素 —— `forum-node-path.ts` 的 `W1`／`W2`（論壇一）、
`S1`~`S3`（論壇二）、`R1`／`R2`（論壇三）讀它的 `top` / `bottom` / `fraction`。
**它的高度一動，那七個節點全部偏掉。**

高度來自兩處，兩處都沒動：

- **行盒**：`ForumArtLine` 的 `::before { content: '\200B' }` 撐出正好 `line-height`
  （＝ `--date-lh`）的行盒，素材是 `::after` 的絕對定位背景、不進流排版。
- **grid 列高**：階梯式的 `grid-template-rows: 127px 114px auto` 原封不動。

### ⚠️ `align-self: start` 是必要的，不是贅寫

grid item 預設 `stretch`，會被拉成**列高**。階梯式的列高是 127／114，而行盒是 124 ——
素材（`::after` 的 `top: 50%`）就會在錯的盒子裡置中：實測第一行往下 1.5px、第二行往上 5px。
`align-self: start` 讓盒子回到自己的行盒高度。
其餘三場的列是 `auto`（＝內容高），`start` 與 `stretch` 同結果，寫上去是為了統一。

## 三、`--date-base`：一個無單位的數字，兩個用途

`--art-base` 必須**無單位**（`ForumArtLine` 用 `calc(--art-w / --art-base * 1em)` 算寬，
帶了 `px` 整式無效、素材寬塌成 0），而它又必須**恆等於該區塊的 `font-size`**。

原本 13 處寫的是 `--date-size: 105px`。改成：

```scss
.forum-event {
  --date-base: 105;                              // 無單位，唯一的來源
  --date-size: calc(var(--date-base) * 1px);      // 舊的用法（font-size、圓框、脊寬）照吃
}
.forum-event__date {
  --art-base: var(--date-base);                  // 素材寬度基準
}
```

各版式的 modifier 改寫 `--date-base`（值不變）。這樣兩個用途共用同一個數字，不會各自漂移。

⚠️ 換上素材後 `--date-base` 只剩兩個作用：撐行盒、當 `--art-base`。
畫面上的字寬完全由素材決定 —— 那些「由稿的字面寬反推字級」的註解仍留著，
因為素材缺件時會退回活文字。

## 四、畫布模式逐場不同（**這一節不能互抄**）

同一份切檔器有兩種畫布模式，四場用的不一樣：

| 模式 | 意思 | 用在 | 理由 |
| --- | --- | --- | --- |
| `group` | 整組共用一塊畫布，列與列的**水平錯位烤進畫布** | 論壇一、三、四 | 實測那三場的稿，同一組每一列都共用同一條錨邊，整塊畫布放進去墨跡就落在對的位置 |
| `ink` | 各列貼齊自己的墨跡，**錯位留給 CSS** | 論壇二 | 它的錯位是 `--stair-x1` / `--stair-x2`，而那兩個常數實測**就是**稿的字面 x 差；畫布再烤一次會位移兩次 |

### `group` 為什麼成立：每一組的稿都共用一條錨邊

用 `align=right` 模式跑一次切檔器，印出每一列自己的墨跡左緣（實測）：

| 組 | 每列 ink 左緣 | 共用的錨邊 | CSS 的錨邊 |
| --- | --- | --- | --- |
| 論壇一 pc | 1 / 1 / 1 / 1 / 0 | 左 | `left: 108px` ✅ |
| 論壇一 pad | 496.53 / 410.61 / 319.13 / 453.64 | 右 688（＝768−80） | `margin-left: auto` ✅ |
| 論壇一 mob | 249.41 / 173.34 / 190.27 / 236.11 / 200.78 | 右 388（＝414−26） | `margin-left: auto` ✅ |
| 論壇三 pc | 899.62 / 750.12 / 762.91 / 917.04 | 右 1172（＝1280−108） | `right: 108px` ✅ |
| 論壇三 pad | 495.45 / 408.90 / 452.81 / 538.49 | 右 688 | `margin-left: auto` ✅ |
| 論壇三 mob | 日期列 0 / 62.94 | 左 | `margin: 92px 0 0` ✅ |
| 論壇四 pc | 714 / 829 / 721 / 715 | 左 714 | `left: 714px` ✅ |
| 論壇四 pad | 0 / 92.20 / 5.61 / 0.80 | 左 0 | （見第六節）|

順帶驗到三個既有常數就是稿的值：論壇四 pc 第二列 829−714 ＝ **115** ＝ `--stair-x1`；
論壇四 pad 92.20 ≒ **92**；論壇三 mob 62.94 ≒ **63**。

### `ink` 為什麼成立：論壇二的階梯常數已經是稿的值

| | pc 稿 | pc CSS | pad 稿 | pad CSS |
| --- | --- | --- | --- | --- |
| `--stair-x1` | 154 | 154 | 98.85 | 99 |
| `--stair-x2` | 323.914 | 324 | 215.25 | 215 |
| `--stair-row1` | 127.28 | 127 | 80.36 | 80 |
| `--stair-row2` | 114.533 | 114 | 80.29 | 80 |

pc 的 154 / 127.28 是這樣量到的：論壇二 pc 的日期是**兩個** node
（`2652:55085` ＝ `2026`、`2652:55083` ＝ `09` ＋ `15 ⊜`），兩份 `export` 匯出裡
**夾帶的同一塊頁面家具**位置差就是兩個 node 原點的距離 ——
`−4952.11 − (−5106.11) = 154`、`−9841.89 − (−9969.17) = 127.28`。

## 五、切檔器（`temp/split-art-svg.mjs`）本次補的五個開關

稿的粒度亂到不能只靠「一個 `<path>` 一列」：

| 開關 | 解決的問題 | 實例 |
| --- | --- | --- |
| `SUBPATH=1` | 稿把**跨列**的字壓成單一 `path` | 論壇四 mob 兩列合成 1 path（19 個 subpath）；論壇二 pc 的 `09`＋`15⊜` 也是 |
| `LIST=1` | 先看成員與索引再決定挑誰 | — |
| `DROP=n` | 丟掉指定成員 | 論壇二 pad 的那一撇是第 186 個成員（69.32×139.60 ＝ `--coreslash-w/h` 的 pad 值） |
| `PICK=n,…` | 只留指定成員（要的比不要的少很多） | 論壇二 mob 的匯出把階梯、地點、時間在 y 上疊在一起（`09` y 108~150 與時間 y 107~124 重疊），純靠列群聚分不開 |
| `KEEP=1,2` | 群聚完只留某幾列，**共用畫布只由留下的列算** | 日期組的匯出一定含地點時間，而它們更寬 |

⚠️ `SUBPATH` 只在 `d` 全是**絕對指令**時安全（相對的 `m` 起點依賴前一段終點，切開就位移）。
Figma 匯出的是絕對指令，切檔器會檢查、遇到小寫直接擲錯。

⚠️ `SUBPATH` 會把同列的 subpath **依 x 重排**，所以輸出的 `d` 字串與 path 級切法不同。
渲染結果相同（nonzero / evenodd 的環繞數都與順序無關），實測論壇四 mob 的時間那一列
兩種切法的墨跡完全一致。

### ⚠️ 兩個**既有**的稿／程式落差（不是本次造成，也刻意沒修）

1. **論壇二 mob 的字級與階梯常數偏大約 30%。**
   稿的字面高 42.4 → 反推字級約 60，程式是 78；錯位稿 68.6／145.6，程式 77／163；
   列距稿 58.2／52.6，程式 73／73。素材照稿的原生尺寸渲染，所以換上素材後
   **字會變小、階梯看起來偏鬆**。要修得連 `--date-base`／`--stair-*`／`--date-lh`
   一起重推 —— 那會改變 `.forum-event__date` 的高度，屬於「階段二 對稿修正」。
   （好消息：`MOB_NODES` 沒有任何節點錨在 `.forum-event__date` 上，所以那次修正
   不會直接帶偏 mob 的設計線。）

2. **論壇二 pad 的日期階梯水平位置差 247px。**
   稿是整組切齊右緣（`2026` 的 ink 左緣在 768 框裡是 327.42、圓框右緣 688），
   程式是貼內容欄左緣（80）。這是版位問題、與素材無關 —— `ink` 模式讓素材落在
   「活文字原本的位置」，所以本次改動沒有讓它變好也沒有變壞。

### 素材缺檔／缺斷點時的失敗方向

`ForumArtLine` 會退回活文字 —— 但日期的圓框烤在素材裡，**退回時圓框會消失**。
所以 spec 對日期這一組要求「三個斷點全滿」，不接受部分覆蓋（其他群組允許）。
